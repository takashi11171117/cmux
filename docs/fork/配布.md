# cmux AFIDE の配布

この fork を「cmux の亜種」として、本家と同じ体験（Homebrew で入り、Sparkle で自動更新される）で配布するための手順。

| 項目 | 値 |
|---|---|
| アプリ名 | `cmux AFIDE` |
| bundle ID | `com.cmuxterm.app.afide` |
| リリース先 | `github.com/takashi11171117/cmux` の Releases |
| appcast | `https://github.com/takashi11171117/cmux/releases/latest/download/appcast.xml` |
| tap | `takashi11171117/cmux-afide` |
| インストール | `brew install --cask takashi11171117/cmux-afide/cmux-afide` |

## なぜ bundle ID を本家と変えるのか

本家の brew 版と同じ `com.cmuxterm.app` にすると、LaunchServices は両者を同一アプリとして扱い、
本家の Sparkle が「新しいバージョンがある」と判断してこの fork を上書きしにくる。
別 ID にすることで共存でき、それぞれが自分の appcast だけを見る。

代償として、設定・ワークスペース・セッションは本家から引き継がれない（初回は空になる）。
これらは `~/Library/Preferences/<bundle-id>.plist` など bundle ID ごとに分かれているため。
唯一 `~/.config/cmux/cmux.json` だけは bundle ID に依存せず共有される。

初回だけ移植を試すなら次のようにコピーできるが、**動作は未確認**。plist の値に bundle ID が
埋まっていると不整合を起こす可能性があるので、必ずバックアップを取ってから試すこと。

```bash
cp ~/Library/Preferences/com.cmuxterm.app.plist \
   ~/Library/Preferences/com.cmuxterm.app.afide.plist
```

## 公式 homebrew-cask ではなく独自 tap である理由

Homebrew の [Acceptable Casks](https://docs.brew.sh/Acceptable-Casks) は、75 stars / 30 forks /
30 watchers 未満のリポジトリを却下する。また fork は元 vendor 名を token の prefix にすることが
求められ、本家 cmux が既に `Casks/c/cmux.rb` として存在する。独自 tap にはこの審査がない。

## 事前準備（一度だけ）

### 1. Developer ID Application 証明書

**これが無いと公証できない。** 現在この Mac にあるのは `Apple Development` と
`iPhone Distribution` だけで、どちらも Mac アプリの外部配布には使えない。

1. https://developer.apple.com/account/resources/certificates で `Developer ID Application` を作成
   （Account Holder 権限が必要）
2. ダウンロードしてキーチェーンに追加
3. ハッシュを控える

```bash
security find-identity -v -p codesigning | grep "Developer ID Application"
```

### 2. Sparkle の署名鍵

```bash
SPARKLE_KEYCHAIN_ACCOUNT=cmux-afide ./scripts/sparkle_generate_keys.sh
```

秘密鍵はキーチェーンに入る。出力された `SPARKLE_PRIVATE_KEY` を次の secrets ファイルに書く。
公開鍵はリリース時に秘密鍵から導出されるため、控えなくてよい。

### 3. secrets ファイル

```bash
mkdir -p ~/.secrets
cat > ~/.secrets/cmux-afide.env <<'ENVEOF'
APPLE_ID=<Apple ID のメールアドレス>
APPLE_TEAM_ID=<Developer ID 証明書のチーム ID>
APPLE_APP_SPECIFIC_PASSWORD=<appleid.apple.com で作る App 用パスワード>
AFIDE_SIGN_HASH=<手順1で控えたハッシュ>
SPARKLE_PRIVATE_KEY=<手順2の秘密鍵>
ENVEOF
chmod 600 ~/.secrets/cmux-afide.env
```

### 4. tap リポジトリ

GitHub に `homebrew-cmux-afide` という名前で公開リポジトリを作り、このリポジトリの隣に置く。
リリーススクリプトが Cask を書き換えて push する。

```bash
git clone https://github.com/takashi11171117/homebrew-cmux-afide ../homebrew-cmux-afide
# もしくは cmux リポジトリ直下に homebrew-cmux-afide/ として置く
```

置かなくてもリリース自体は通る（Cask 更新だけスキップされる）。

## リリース

```bash
./scripts/fork/release-afide.sh v0.1.0
```

このスクリプトが行うこと。

1. secrets と署名 ID を検証（`Developer ID Application` でなければここで止まる）
2. entitlements をテンプレートから生成し、チーム ID を差し込む
3. GhosttyKit を ReleaseFast でビルド
4. `PRODUCT_NAME` / `PRODUCT_BUNDLE_IDENTIFIER` を上書きして Release ビルド
5. Sparkle の公開鍵と、この fork の appcast URL を Info.plist に注入
6. 署名 → 公証 → staple
7. DMG を作成 → 公証 → staple
8. appcast.xml を生成
9. GitHub Release を作成しアセットをアップロード
10. tap の Cask を更新して push

## 本家スクリプトとの関係

`scripts/build-sign-upload.sh` は書き換えていない。あれは upstream 追従の対象で、
fork 固有の値（bundle ID、チーム ID、cask token、zap パス）を入れると毎回コンフリクトする。

代わりに `scripts/fork/release-afide.sh` として複製した。**upstream がリリース手順を変えたら、
このファイルを手で追従させる必要がある。** それが本家を触らないことの対価。

## entitlements の差分

`cmux.entitlements` には本家のチーム ID (`7WLXT3NR37`) が埋まっているため、そのままでは
署名が通らない。`scripts/fork/afide.entitlements.tmpl` で置き換えている。

本家から削除した項目:

- `com.apple.developer.web-browser.public-key-credential` — Apple の個別承認が必要な
  entitlement。承認されていないアカウントで署名すると失敗する。この fork では passkey 関連の
  ブラウザ機能を使わない前提で外した。必要になったら Apple に申請した上で戻すこと。
