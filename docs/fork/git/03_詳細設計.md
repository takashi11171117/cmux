## 2. `RightSidebarMode.git` の追加

### 2.1 enum 本体

`[実コード: Sources/RightSidebarPanelView.swift:16-22]` に case を足す。

```swift
enum RightSidebarMode: String, CaseIterable, Codable, Sendable {
    case files
    case git          // 追加。files の次に置く（タブ順が allCases 順のため）
    case find
    case sessions
    case feed
    case dock
    case customSidebar = "custom-sidebar"
}
```

**タブ順は宣言順で確定** `[実コード]`。タブは
`availableModes.map { RightSidebarModeBarItem(kind: .mode($0)) }`
`[実コード: Sources/RightSidebarPanelView.swift:152]` で作られ、その
`availableModes` は `allCases.filter { ... }`
`[実コード: Sources/RightSidebarMode+Availability.swift:30]`。並べ替えは無いため、
enum の宣言順がそのままタブ順になる。

### 2.2 case 追加で埋める必要がある箇所

`switch` の網羅性でコンパイラが検出するものと、しないものがある。**しないものが危険**。

| 箇所 | 内容 | 検出 | 出所 |
|---|---|---|---|
| `label` | 表示名「Git」 | ○ | `[実コード: RightSidebarPanelView.swift:24-32]` |
| `symbolName` | SF Symbol | ○ | `[同:35-43]` |
| `shortcutAction` | ショートカット。新規に足すなら `KeyboardShortcutSettings` 側も要る | ○ | `[同:46-54]` |
| `isAvailable(feedEnabled:dockEnabled:)` | 常に true とするか | ○ | `[実コード: RightSidebarMode+Availability.swift:40-45]` |
| `FileExplorerRootSyncPolicy.shouldSyncFileExplorerStore` | **true にする必要がある** | ○ | `[実コード: RightSidebarPanelView.swift:73-80]` |
| `from(cliArgument:)` | `"git"` を受ける | **×** | `[実コード: RightSidebarMode+Availability.swift:5-20]` |
| `paneModes` | ペインとして開けるか | **×** | `[実コード: RightSidebarPanelView.swift:59]` |

`from(cliArgument:)` と `paneModes` は `switch` に `default` があるか配列リテラル
のため、**case を足してもコンパイルは通り、実行時に機能しないだけ**になる。
`customSidebar` を参照する箇所は 20 あり `[実測: grep]`、これらを漏れなく見る。

### 2.3 `shouldSyncFileExplorerStore` を true にする理由

```swift
switch mode {
case .files, .find:   return true
case .sessions, ...:  return false
}
```
`[実コード: Sources/RightSidebarPanelView.swift:75-79]`

Git モードは `FileExplorerStore` の git status を購読するため、ストアが同期
されていないと一覧が更新されない（FR-G03）。`.files, .find, .git` を true にする。

## 3. 一覧 UI

### 3.1 データ源

新しい取得経路は作らない。`FileExplorerStore` が既に保持している。

| 事実 | 出所 |
|---|---|
| `GitStatusProvider` を保持 | `[実コード: Sources/FileExplorerStore.swift:755-758]` |
| 根の切替時に `refreshGitStatus()` | `[同:818-821]` |
| ディレクトリ監視イベントごとに `reload()` + `refreshGitStatus()` | `[同:878-882]` |

**この結果を読むだけ**でよい。ポーリング・独自監視は行わない（FR-G03）。

`refreshGitStatus()` は provider の型でローカルと SSH を振り分け、どちらも
`gitStatusByPath` に格納する `[実コード: Sources/FileExplorerStore.swift:824-853]`。
一覧側は分岐を持たない。

`fetchStatus` の戻りは `[String: GitFileStatus]`（パス→状態）
`[実コード: Sources/GitStatusProvider.swift:24]`。一覧はこれをパス順に並べる
`[設計判断]`。

### 3.2 SwiftUI 構造の制約

`CLAUDE.md` の規約により、以下を守る。

- `ForEach` の下の行 view は observable store への参照を持たない
- `body` から state を書かない

**前例**: コードレビューカラムのタブは `CodeReviewTabActions` という callback
の束を渡すことでこれを守っていた（現在は Workspace 化により削除済み）。
Git 一覧も同じ形にする。参照実装として `IndexSectionActions` /
`SectionGapActions` / `SessionSearchFn` が挙がっている `[出所: CLAUDE.md]`。

違反すると 100% CPU のスピンループが再発する（upstream #2586）。

## 4. 一覧から差分を開く

### 4.1 経路（実装後に判明した実態）

**当初の想定は誤りだった。** 「URL を得て `newBrowserSurface` に渡す」と書いていたが、
差分 URL はアプリ側で作れない。アプリは `cmux` CLI をサブプロセスとして起動し、
CLI が差分 HTML を生成してソケット経由で「この URL を開け」と返す。

```
AppDelegate.openDiffInCodeReviewColumn()
  → Process(bin/cmux diff --unstaged --code-review-column --cwd ...)
      `[実コード: Sources/AppDelegate.swift launchDiffViewerProcess]`
  → CLI が /tmp/cmux-diff-viewer-<uid>/diff-<ts>-<rand>-viewer.html を生成
  → socket: browser.open_split { code_review_column: true }
  → TerminalController が分岐して AppDelegate.openBrowserInCodeReviewColumn(url:)
  → CodeReviewPanelState.showBrowser(url:)
```

分割が起きるのは最後の一段（ソケットの受け口）だったため、そこに opt-in の分岐を
入れた。`cmux diff` の既定は `split_right` のまま
`[実測: placement_strategy が split_right のままであることを確認]`。

### 4.1.1 差分タブの再利用はスキームで判定する

CLI は**呼び出しごとに別ファイル名**の HTML を書く。

```
diff-1787069026-4313A71E-viewer.html
diff-1787069026-D9FFE649-viewer.html
```

URL 一致で既存タブを探す実装では一致せず、3 回開けばタブが 3 枚になった
`[実測]`。差分は `cmux-diff-viewer` スキームで判定し、既存の差分タブを
新しい URL へ遷移させる。ファイルはパスが安定するため URL 一致のままでよい。

### 4.2 カラムに開く方法

カラムは自前の `Workspace` を持ち、ブラウザサーフェスを作れる。

| 事実 | 出所 |
|---|---|
| カラムは `Workspace` を保持する | `[実コード: Sources/CodeReviewPanelState.swift]` |
| タブバーに `.builtIn(.newBrowser)` を持つ | `[同]` |
| ファイルを開く際は `newFilePreviewSurface` / `newMarkdownSurface` を使い分ける | `[同]` |

差分も**ブラウザサーフェスとして**カラムの pane に開く `[設計判断]`。
使う API は確認済み `[実コード: Sources/Workspace.swift:8664-8671]`。
ただし URL を渡す側は CLI 経由になる（§4.1 参照）。

```swift
func newBrowserSurface(
    inPane paneId: PaneID,
    url: URL? = nil,
    initialRequest: URLRequest? = nil,
    focus: Bool? = nil,
    ...
) -> BrowserPanel?
```

`url` に `cmux-diff-viewer://` を渡す形になる。ファイルを開く既存実装
（`newFilePreviewSurface` / `newMarkdownSurface` の使い分け）と同じ並びに置ける。

### 4.3 現在の配置戦略を変える必要はない

`cmux diff` の `placement_strategy: split_right` `[実測]` は CLI の既定であり、
そのままにする。Git 一覧からの導線だけがカラムを使う。

**理由**: `cmux diff` を直接叩く既存の使い方を壊さないため `[設計判断]`。

## 6. テスト方針

`CLAUDE.md` の規約により、`cmuxTests/` に追加するファイルは pbxproj への
4 箇所登録が必要。登録漏れは「Executed 0 tests」で緑になる。
`./scripts/lint-pbxproj-test-wiring.sh` で検出する。

| テスト | 対象 |
|---|---|
| モード追加 | `from(cliArgument: "git")` が `.git` を返す |
| モード追加 | `availableModes()` に `.git` が含まれる |
| 同期ポリシー | `shouldSyncFileExplorerStore(mode: .git)` が true |
| 一覧の並び | パス順に並ぶ／空リポジトリで空になる |
| 種別の対応 | 5 種すべてが区別される |

**UI そのもの（クリックで開く等）は単体テストで届かない**ため、
`docs/fork/手動テスト仕様書.md` に項目を追加する。
