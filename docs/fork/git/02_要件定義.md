# cmux fork: Git 差分・変更一覧 要件定義

出所の凡例と調査日は `01_要求定義.md` に準ずる。

## 1. 機能要件

### FR-G01 右サイドバーに Git モードを追加する

`RightSidebarMode` に `git` を追加する。

| 項目 | 内容 | 出所 |
|---|---|---|
| 追加先 | `enum RightSidebarMode: String, CaseIterable, Codable, Sendable` | `[実コード: Sources/RightSidebarPanelView.swift:16]` |
| raw value | `"git"` | `[設計判断]` 既存は `files` `find` `sessions` `feed` `dock` `custom-sidebar`。単語1つのものは小文字そのまま |
| 表示名 | 「Git」 | `[設計判断]` |
| タブ順 | files の次 | `[設計判断]` ファイルツリーと役割が近いため |

**受け入れ基準**

- 右サイドバーのタブに Git が出る
- `cmux right-sidebar git` で切り替わる
- 再起動後も選択が保持される（`Codable` なので既存の永続化に乗る `[実コード: 同上]`）

### FR-G02 変更ファイルを一覧表示する

**受け入れ基準**

- 作業ツリーの変更ファイルが、パスと変更種別つきで並ぶ
- 変更種別は modified / added / deleted / renamed / untracked の5種を区別する
  `[実コード: Sources/GitFileStatus.swift:1-3]`
- Git リポジトリでないフォルダを開いているときは空表示になり、エラーにならない
  （`fetchStatus` はリポジトリ根を解決できないとき空辞書を返す
  `[実コード: Sources/GitStatusProvider.swift:25]`）
- 変更が無いときは「変更なし」と分かる表示になる

### FR-G03 一覧は自動で更新される

**受け入れ基準**

- ファイルを保存すると、数秒以内に一覧へ反映される
- 別のターミナルで `git add` しても反映される
- 一覧のために独自のポーリングを行わない

**実現方法**: `FileExplorerStore` の状態を購読する。同ストアはディレクトリ監視
イベントごとに `reload()` と `refreshGitStatus()` を呼ぶ
`[実コード: Sources/FileExplorerStore.swift:878-882]`。

### FR-G04 一覧から差分を開く

**受け入れ基準**

- 項目をクリックすると、そのファイルの差分が開く
- 開き先はコードレビューカラム
- 10 個続けて開いても、ターミナル側のペイン構成が変化しない
- カラムが閉じている場合は開いてから表示する（FR-G07 参照）

### FR-G05 差分ソースを切り替える

**受け入れ基準**

- unstaged / staged / branch / last-turn を切り替えられる
  `[実コード: CLI/cmux_open.swift:653-694]`
- 既定は unstaged `[設計判断]` 「いま何を変えたか」が最も見たい情報のため
- 選択は右サイドバーの表示状態として保持される

### FR-G06 リポジトリ根の扱いは既存踏襲

一覧に出るのは、ファイルツリーの根に含まれる変更のみとする。

**根拠**: `fetchStatus` はリポジトリ根を解決したうえで explorer root に含まれる
ものだけを返し、キーは呼び出し側の綴りで出す
`[実コード: Sources/GitStatusProvider.swift:24-36]`。ここを変えるとファイル
ツリーの変更マークと一覧の内容が食い違う。

**受け入れ基準**: ツリーに出ないファイルの変更は一覧にも出ない。

### FR-G07 [要確認] カラムが閉じているときの挙動

差分を開こうとしたときカラムが非表示なら、どうするか。

- 案A: 自動的に開く
- 案B: 開かず、タイトルバーのトグルを促す

**案A を推す** `[設計判断]`。ファイルを開く既存経路は `show(filePath:)` の
先頭で `isVisible = true` としており、同じ挙動に揃う
`[実コード: Sources/CodeReviewPanelState.swift]`。ただし利用者の意図に反して
画面が動く可能性があるため、実装前に確認する。

## 2. 非機能要件

### NFR-G01 リポジトリをロックしない

git 実行は `GIT_OPTIONAL_LOCKS=0` 付きで行う。

**根拠**: 既存の `GitStatusProvider` がそうしている
`[実コード: Sources/GitStatusProvider.swift:6-7]`。別プロセスの git 操作を
妨げないため。新しく git を実行する箇所を作る場合も同じ扱いにする。

### NFR-G02 一覧の描画がタイピングを妨げない

**根拠**: `CLAUDE.md` の「SwiftUI list boundaries」規約。`LazyVStack` /
`List` / `ForEach` の下にある view は observable store への参照を持ってはならず、
`body` から state を書いてはならない。違反すると 100% CPU のスピンループが再発する
（upstream #2586）。

**受け入れ基準**: 一覧を表示した状態でターミナルに入力しても、体感の遅延が無い。

### NFR-G03 既存の差分ビューアを改変しない

差分の描画・コメント機能には手を入れない。開く場所だけを変える。

**根拠**: 既存が動作しており `[実測]`、レビューコメント機能が乗っている
`[実コード: Sources/Panels/DiffCommentsBridge.swift]`。改変すると影響範囲が
本書のスコープを超える。

### NFR-G04 ローカライズ

追加する文字列はすべて `String(localized:)` を使い、
`Resources/Localizable.xcstrings` に en / ja 両方を入れる。

**根拠**: `CLAUDE.md` の規約。
