## 1. 何を欲しいと言われたか

> 「Git の差分とかツリーを見れるようにするって難しいかな？」
> 「今ある右パネルに機能を入れられる？」

コードレビューを cmux の中で完結させたい、というのが背景。現状は差分を見るのに
ターミナルで `git diff` を打つか、外部ツールへ移る必要がある。

## 2. 現状（実コードで確認した事実）

### 2.1 差分ビューアは既に存在する

`cmux diff` は動作し、WebView 上に差分を描画する。

| 事実 | 出所 |
|---|---|
| 4 種の差分ソースを持つ（unstaged / staged / branch / last-turn） | `[実コード: CLI/cmux_open.swift:653-694]` |
| `cmux-diff-viewer://` という専用スキームの WebView を開く | `[実コード: Sources/TerminalController+DiffViewerTrust.swift:19]` |
| 開き方は `split_right`（ターミナル側のペインを分割する） | `[実測: cmux diff --unstaged --json の応答 placement_strategy]` |
| コマンドパレットに「Open Directory Diff Viewer」がある | `[実コード: Sources/ContentView.swift:7835-7836]` |
| 差分ビューア上にレビューコメント機能がある | `[実コード: Sources/Panels/DiffCommentsBridge.swift, Sources/TerminalController+CommentsCommands.swift:4]` |

**つまり差分の描画そのものは作る必要がない。**

### 2.2 Git 状態の取得も既に存在する

| 事実 | 出所 |
|---|---|
| `git status --porcelain=v1 -z` を実行して path→状態の辞書を返す | `[実コード: Sources/GitStatusProvider.swift:24-36]` |
| 状態は modified / added / deleted / renamed / untracked の5種 | `[実コード: Sources/GitFileStatus.swift:1-3]` |
| `GIT_OPTIONAL_LOCKS=0` を使いリポジトリをロックしない | `[実コード: Sources/GitStatusProvider.swift:6-7]` |
| SSH 経由のリモート取得にも対応する | `[実コード: Sources/GitStatusProvider.swift:38]` |
| ファイルツリーがこれを使い、行に変更マークを出す | `[実コード: Sources/FileExplorerStore.swift]` |

**つまり変更ファイルの列挙も作る必要がない。**

### 2.3 右サイドバーはモード切替式

| 事実 | 出所 |
|---|---|
| `RightSidebarMode` は `String, CaseIterable, Codable` の enum | `[実コード: Sources/RightSidebarPanelView.swift:16]` |
| 現在 6 モード（files / find / sessions / feed / dock / custom-sidebar） | `[実コード: Sources/RightSidebarPanelView.swift:17-22]` |
| CLI から `cmux right-sidebar <files\|find\|vault\|sessions\|feed\|dock>` で切替できる | `[実測: cmux-debug-cli.sh --help]` |

**つまりタブを増やす器も既にある。**

### 2.4 足りていないもの

上記を踏まえると、本当に無いのは次の2つだけ。

1. **変更ファイルの一覧 UI** — 状態の取得はできるが、それを一覧として見せる画面が無い
2. **一覧から差分を開く導線** — 差分は開けるが、常に `split_right` でターミナルを分割する

## 3. 業務要求（GREQ-xx）

### GREQ-01 変更ファイルを一覧で見たい

作業ツリーの変更を、ファイル名と変更種別（追加/変更/削除/未追跡）の一覧で見たい。
ターミナルで `git status` を打たずに、常に視界に置いておきたい。

### GREQ-02 一覧から差分をすぐ開きたい

一覧の項目をクリックしたら、そのファイルの差分が出てほしい。何度もクリックする
うちにターミナルが分割で埋まっていく、という状態は避けたい。

### GREQ-03 右サイドバーに置きたい

新しいパネルを増やすのではなく、既にある右サイドバー（ファイル/検索/ボールト）の
タブとして追加したい。

> 「今ある右パネルに機能を入れられる？」

### GREQ-04 差分は広い場所で読みたい

一覧は狭くて構わないが、差分は広い場所で読みたい。コードレビューカラムがその
役割を持っている。

## 4. スコープ

### 4.1 やること

- 右サイドバーに Git タブを追加し、変更ファイルを一覧表示する
- 一覧から差分を開く。開き先はコードレビューカラム
- 差分ソース（unstaged / staged / branch / last-turn）を切り替えられる

### 4.2 やらないこと

以下は今回の範囲外とする。理由を添える。

| 項目 | 理由 |
|---|---|
| コミット・ステージング操作 | 「見れるようにする」が要求。書き込み操作は要求されていない |
| 差分ビューアそのものの改修 | 既存が動作しており、不満は表明されていない |
| ブランチ切替・履歴閲覧 | 同上。要求は「差分とツリー」 |
| リモート（SSH）リポジトリ対応 | 対象外にしようとしたが、**除外する方が手間**だった。`refreshGitStatus()` が provider の型で振り分け、結果を同じ辞書に入れる `[実コード: Sources/FileExplorerStore.swift:824-853]`。購読するだけで両方効く |

## 5. 先に決める必要があること

### 5.1 [解決済] 一覧のリポジトリ根は既存踏襲

ファイルツリーの根に含まれる変更のみを出す。要件定義 FR-G06 で確定。

`GitStatusProvider.fetchStatus` は内部でリポジトリ根を解決し、**explorer root に
含まれるものだけを返す** `[実コード: Sources/GitStatusProvider.swift:24-36]`。
ここを変えるとファイルツリーの変更マークと一覧の内容が食い違うため、踏襲する。

つまり「ツリーに出ないファイルの変更は一覧にも出ない」。

### 5.2 [解決済] 更新契機はディレクトリ監視に相乗りする

調査の結果、既存の仕組みに相乗りできることが分かった。

| 事実 | 出所 |
|---|---|
| `FileExplorerStore` が `GitStatusProvider` を保持する | `[実コード: Sources/FileExplorerStore.swift:755-758]` |
| 根を切り替えたときに `refreshGitStatus()` を呼ぶ | `[実コード: Sources/FileExplorerStore.swift:818-821]` |
| ディレクトリ監視イベントごとに `reload()` と `refreshGitStatus()` を呼ぶ | `[実コード: Sources/FileExplorerStore.swift:878-882]` |

ファイル変更を検知した時点で git status が引き直されるため、**Git 一覧は
`FileExplorerStore` の状態を購読するだけでよい**。ポーリングも独自の監視も要らない。

### 5.3 [設計判断] 差分の開き先はコードレビューカラム

`cmux diff` は現在 `split_right` でターミナルを分割する `[実測]`。一覧から
何度も開くとターミナルが分割で埋まるため、カラムに開く。これはファイルを
カラムに開くようにしたのと同じ理由で、その実装が前例になる
`[実コード: Sources/FileOpenSocketSupport.swift:145-180]`。

ただし「カラムが閉じているとき」の扱いは `[要確認]`。自動で開くか、開かないか。

## 6. 完成条件

- 右サイドバーに Git タブが出る
- 作業ツリーの変更ファイルが、変更種別つきで一覧に出る
- 一覧の項目をクリックすると差分が開く
- 差分を10回開いてもターミナルのペイン構成が変わらない
- リポジトリでないフォルダを開いても壊れない（一覧が空になる）
