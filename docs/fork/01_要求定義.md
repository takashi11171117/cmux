## 0. 検証サマリ（Claude 追記）

原文は「cmux に既にこれらの機能があるから再実装しない」という前提で組まれている。その前提を実コードで検証した結果、**前提はおおむね正しいが、残作業の見積もりと upstream 戦略が実態と合っていない**。

### 結論1: 残差分は「シンタックスハイライト」と「行番号」の2つだけ

cmux HEAD には既に NSTextView ベースの編集・保存機能がある `[実コード: Sources/Panels/FilePreviewTextEditor.swift, 477行]`。MarkdownPanel と FilePreviewPanel が `FilePreviewTextEditingPanel` を実装して共有している `[実コード: Sources/Panels/MarkdownPanel.swift:16]`。

| §13 の MVP 項目 | 実態 |
|---|---|
| Text Edit / Save | ✅ 実装済み `[実コード: FilePreviewPanel.swift:1302, MarkdownPanel.swift:307 の saveTextContent()]` |
| Undo / Redo | ✅ 実装済み |
| Cmd+F / Replace | ✅ 実装済み |
| File Watch / 外部変更検知 | ✅ 実装済み `[実コード: MarkdownPanel.swift:429-435 の FileWatcher]` |
| 未保存バッファの管理 | ✅ `isDirty` 追跡あり `[実コード: FilePreviewPanel.swift:985]` |
| **Syntax Highlight** | ❌ **未実装（実質ここだけが差分）** |
| **Line Number** | ❌ **未実装** |

したがって本計画は「Editor を新規に作る」話ではなく、**既存 `FilePreviewTextEditor` を拡張する**話である。

### 結論2: upstream PR 戦略は成立しない

`[GitHub API]` upstream `manaflow-ai/cmux` は 2026-01-28 作成、Star 26,097 / Fork 2,217。PR 実績は **open 2,518件 / merged 3,571件 / closed 4,340件**。

- タイトルに editor を含む PR は **20件以上が open で、新規エディタ機能のマージ実績はゼロ**
- merged 側で editor を含むのは6件だけで、**全部が既存機能のバグ修正**（TextKit 1 強制 #5257、矢印キー移動と word-wrap #5247 など）

open PR が2,518件ある環境では PR を出すこと自体の期待値が低い。§39 は削るか大幅に弱めるべき。

### 結論3: fork はまだ素の状態

`[GitHub API]` `takashi11171117/cmux` は **独自コミット0 / upstream から12コミット遅れ**。着手前に upstream 追従が必要。

### 先に決めるべき設計判断

**Panel 層に足すか、Surface 層に足すか。** 現状 `CmuxSurfaceType` は `terminal` / `browser` / `project` の3種のみ `[実コード: Sources/CmuxConfig.swift:1620-1624]`。Surface は Session Restore の永続化単位に直結するため、§18・§30 の「Session Restore を壊さない」に影響する。原文 §6 は Panel 層前提で書かれているが根拠が示されていない。競合 PR の #4801 は Surface 層に足す方式を採っている `[PR: 4801]`。

# cmux + Warp系IDE機能 実装指針 v0.1

## 1. 目的

cmuxの強みである

- Workspace / Session管理
- Terminal
- Browser Pane
- Session Restore
- 複数Claude Code運用

を維持したまま、Warpで便利だった

- File Tree
- Markdown Preview
- Image Preview
- Diff Viewer
- Code Preview / 軽量Editor

を統合する。

目標はVS Codeの完全代替ではない。

**Claude Code / Codex等のAgentを主役にし、人間は必要な時だけ成果物・コード・画像・Markdownを確認できる「Agent-first IDE」**を作る。

---

## 2. 最終イメージ

```text
┌───────────────┬──────────────────────────┬────────────────────┐
│ Workspaces    │ Claude / Terminal        │ Files / Preview    │
│               │                          │                    │
│ DiveCut       │ > 実装しています...     │ src/               │
│ VisualPark    │                          │ ├ components/      │
│ Client A      │                          │ ├ lib/             │
│ Client B      │                          │ └ app/             │
│               │                          │                    │
│               │                          │ README.md          │
│               │                          │ output.png         │
└───────────────┴──────────────────────────┴────────────────────┘
```

普段は中央のAgentのみを見る。

必要な時だけ右側で、

```text
.md
→ Markdown Preview

.png / jpg
→ Image Preview

.swift / ts / dart / php
→ Code Viewer / Editor

diff
→ Diff Viewer
```

を表示する。

## 34. 技術リスク

### 1. Editor dependency
Syntax Highlightライブラリの品質。

### 2. File Watch
AIが短時間に大量編集するためイベント数が多い。

### 3. Save conflict
Claudeが同じファイルを編集している最中に人間が保存するケース。

### 4. Large File
巨大JSON、log等をEditorで開かない。

### 5. Session Persistence
Editor状態追加によって既存restoreを壊さない。

---

## 35. Conflict対策

外部変更を検出した場合、

勝手に人間の編集中内容を消さない。

```text
File changed externally.

Reload
Compare
Keep Mine
```

のような処理を検討。

Agent-first IDEでは普通のIDE以上に重要。

> 🔴 **訂正: 「検討」ではなく MVP 必須。ただし土台は既にある**
> §13 の MVP に Save が入っており、§34-3 で保存衝突をリスクに挙げている以上、衝突時の動作は **MVP で決まっていなければならない**。
> 既存実装は `isDirty` を追跡し、外部変更時に未保存バッファを破棄せず再読込する `[実コード: Sources/Panels/FilePreviewPanel.swift:985,1176,1193 / MarkdownPanel.swift:271]`。
> したがって残作業は **Reload / Compare / Keep Mine の選択 UI** であり、検知機構の新規実装ではない。

## 39. Upstream PR

> 🔴 **訂正: この戦略は成立しない。削るか大幅に弱めること**
> `[GitHub API]` upstream の PR 実績は **open 2,518件 / merged 3,571件 / closed 4,340件**（2026-01-28 作成、Star 26,097 / Fork 2,217）。
> - タイトルに editor を含む PR は **20件以上が open で、新規エディタ機能のマージ実績はゼロ**
> - merged 側で editor を含むのは6件のみで、**全部が既存機能のバグ修正**（#5257 TextKit 1 強制、#5247 矢印キー移動と word-wrap、#6956 IME 切替 など）
>
> open PR が2,518件ある環境では PR を出すこと自体の期待値が低い。**upstream 還元を前提に差分を制約するコストに見合わない。**
> ただし §38 の「upstream の Terminal / Workspace 構造を大きく変更しない」は、**追従コストを下げるという別の理由で有効**なので維持してよい。

完成度が上がったら、

- Code Editor
- File Routing
- Inspector改善

を機能単位でupstream PRすることも検討。

自社forkだけに巨大差分を抱えない。

## 41. 最終コンセプト

目指すものは、

**VS Codeの中にTerminalを置くことではない。**

逆に、

> **Agent / Terminalを中心に置き、必要なIDE機能だけを周辺に置く。**

という開発環境。

```text
Traditional IDE

Editor
├ Terminal
├ AI
└ Git
```

ではなく、

```text
Agent-first IDE

Agent / Terminal
├ Files
├ Preview
├ Diff
└ Lightweight Editor
```

にする。

cmuxのセッション管理とWarpの軽量IDE体験を組み合わせた、

**Claude Code / Codex時代の開発環境**

を目標とする。
