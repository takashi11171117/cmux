## 1. 何を欲しいと言われたか

> 「git の過去履歴と git graph 的なのみれるようにって難しいかねー？」

背景は先行機能と同じで、コードレビューを cmux の中で完結させたい。現状、過去の
コミットを見るにはターミナルで `git log` を打つか、外部ツールへ移る必要がある。

## 2. 現状（実コードで確認した事実）

### 2.1 リポジトリの解決と監視は既にある

`CmuxGit` が作業ツリー根・`.git` ディレクトリ・common ディレクトリを保持する
`ResolvedGitRepository` を持つ `[実コード: Packages/macOS/CmuxGit/Sources/CmuxGit/Model/ResolvedGitRepository.swift:16-30]`。

HEAD とその参照先の値を連結した署名を返す `gitHeadSignature(repository:)` があり、
**コミットが増えたことの検出に流用できる**
`[実コード: Packages/macOS/CmuxGit/Sources/CmuxGit/Parsing/GitMetadataService+Refs.swift:62-77]`。

### 2.2 右サイドバーはモード切替式で、Git タブが既にある

```swift
enum RightSidebarMode: String, CaseIterable, Codable, Sendable {
    case files
    case git      // 変更ファイル一覧（先行機能）
    case find
    case sessions
    case feed
    case dock
    case customSidebar = "custom-sidebar"
}
```
`[実コード: Sources/RightSidebarPanelView.swift:16-28]`

宣言順がタブ順になる（`allCases.filter` を並べ替えずに map しているため）
`[実コード: 同 18-22 のコメント]`。

### 2.3 一覧の作り方は確立している

先行機能で、平坦化した行を1本の `ForEach` に流す型ができている
`[実コード: Sources/GitChangeTreeRow.swift]`。折りたたみ状態は境界の上の `Set` が
持ち、行より下に observable を置かない。これは upstream #2586 の再発防止のための
制約で、履歴一覧にもそのまま効く。

### 2.4 差分の出し方も確立している

`GitFilePatchCommand` が「どのリビジョンと比べるか」を値型で決める
`[実コード: Sources/GitFilePatchCommand.swift]`。現在は `HEAD` 比較と
`--no-index` の2通りだが、**任意のコミット間に広げる余地がある**。

カラムへ開く経路は `openFileDiffInCodeReviewColumn(filePath:isUntracked:repositoryRoot:)`
`[実コード: Sources/AppDelegate.swift:7063]`。

### 2.5 カラムに HTML を開く口はある

`CodeReviewPanelState.showBrowser(url:)` がカラムにブラウザサーフェスを開く
`[実コード: Sources/CodeReviewPanelState.swift:112-135]`。差分は
`cmux-diff-viewer://` スキームで判定してタブを1枚に保つ。それ以外の URL は
**完全一致**で既存タブを探す `[同:127-134]`。

### 2.6 足りていないもの

- コミット履歴を読む手段が無い（`git log` を叩いている箇所は存在しない `[実測: grep]`）
- コミット単体の差分を開く経路が無い（現在は作業ツリーの差分のみ）
- グラフのレーンを計算する仕組みが無い

## 3. 業務要求（HREQ-xx）

### HREQ-01 コミット履歴を一覧で見たい

いつ・誰が・何をしたかを、ターミナルへ降りずに追えること。

### HREQ-02 コミットの差分をすぐ開きたい

一覧の行から、そのコミットが何を変えたかをすぐ読めること。導線は先行機能の
「行クリック → カラムに差分」と揃える `[設計判断]`。

### HREQ-03 分岐とマージを図で見たい

直線的な履歴だけでなく、どこで分かれてどこで合流したかを把握できること。

### HREQ-04 大きいリポジトリで固まらない

cmux 本体のような数万コミットのリポジトリでも、開いた瞬間に固まらないこと。

## 4. スコープ

### 4.1 やること

- 右サイドバーに履歴タブを追加する
- コミット一覧（ハッシュ・件名・作者・日時）を表示する
- 行から、そのコミットの差分をカラムに開く
- ページングで履歴を継ぎ足す
- 分岐・マージを持つグラフをカラムに表示する

### 4.2 やらないこと

- **コミット・チェックアウト・リベース等の書き込み操作**。読むだけに限る `[設計判断]`。
  破壊的操作を持ち込むと、失敗時の復旧まで面倒を見る必要があり、規模が跳ね上がる
- **リモートとの通信**（fetch / pull / push）。ローカルの `.git` だけを読む `[設計判断]`
- **ブランチやタグの作成・削除**
- **コミット内の行単位の blame**
- **検索**（`git log --grep`）。まず一覧が要る `[設計判断]`

### 4.3 段階

先に一覧、あとからグラフ `[設計判断]`。

一覧だけで日常の用は足りる。行クリックの導線が確定してから同じデータでグラフを
足す方が手戻りが無い。グラフのレーン計算は一覧の表示形式に依存しないので、
分けても二度手間にならない。

## 5. 先に決める必要があること

### 5.1 [設計判断] 履歴とグラフは置き場所を分ける

必要な横幅が違う。

| | 必要な幅 | 置き場所 |
|---|---|---|
| コミット履歴 | 狭くてよい | 右サイドバーの新タブ |
| コミットグラフ | 広くないと潰れる | コードレビューカラム |

右サイドバーの幅では、レーンを持つグラフは線が重なって読めない。逆に履歴一覧は
狭くても機能する。先行機能が「一覧はサイドバー、差分はカラム」で成立している
`[実コード: docs/fork/git/01_要求定義.md GREQ-03/GREQ-04]` ので、同じ分け方に揃える。

### 5.2 [設計判断] リポジトリ根は先行機能と同じものを使う

先行機能は `FileExplorerStore.rootPath` を使い、グループ内のセッションは
グループのターミナルのディレクトリを借りる `[実コード: Sources/GroupDirectoryFallback.swift]`。
履歴が別の根を見ると、同じ画面の2つのタブが別のリポジトリを指すことになる。

### 5.3 [設計判断] 更新契機は HEAD 署名の変化

先行機能の変更ファイル一覧はディレクトリ監視に相乗りしている。履歴は
**コミットが増えたときだけ**更新すればよく、ファイル保存のたびに `git log` を
回す必要は無い。`gitHeadSignature` の変化を契機にする
`[実コード: GitMetadataService+Refs.swift:62-77]`。

### 5.4 [決定] グラフの描画方式

**固定パスの `file://`** を採る。実測 `[実測: 2026-08-27]`:

- `BrowserPanel.browserLoadRequest` は `url.isFileURL` を判定して
  `WKWebView.loadFileURL(_:allowingReadAccessTo:)` を呼ぶ経路が既にある
  `[実コード: Sources/Panels/BrowserPanel.swift:978-984]`
- `browserEmbeddedNavigationSchemes` には `"file"` が入っており、ブラウザパネルで
  受理される既定のスキームの一つ `[実コード: 同:988-995]`
- `CodeReviewPanelState.showBrowser(url:)` の非スキーム経路は**完全一致**で
  既存タブを探す `[実コード: Sources/CodeReviewPanelState.swift:127-134]`。
  固定パスなら URL が変わらないのでタブ再利用がそのまま効く

独自スキームは不要。1ワークスペース1つの HTML ファイルを一時ディレクトリに書き
出して上書きし、その `file://` URL を `showBrowser` に渡す。`bypassRemoteProxy` は
差分ビューア固有の要求で、ローカル `file://` は remote proxy を通らないため不要。

### 5.5 [要確認] 1ページあたりの件数と先読み

数万コミットを一度に読むと固まる。`--max-count` と `--skip` で刻むが、
**初回に何件読むか**と**どこまでスクロールしたら次を読むか**は実測で決める。
先行機能で 51KB のファイルが問題なく扱えている一方、`git log` の所要時間は
リポジトリ規模に依存するため、机上では決められない。

## 6. 完成条件

段階Aは、次がすべて満たされたとき完成とする。

- 右サイドバーに履歴タブがあり、コミットが新しい順に並ぶ
- 各行にハッシュ・件名・作者・相対日時が出る
- 行をクリックすると、そのコミットの差分がカラムに開く
- 下までスクロールすると続きが読み込まれる
- コミットしても、リポジトリを切り替えても、一覧が追随する
- git 管理外のフォルダで開いてもエラーにならない
- 数万コミットのリポジトリで、開いた瞬間に固まらない

段階Bは、次を追加で満たしたとき完成とする。

- グラフがカラムに開き、分岐とマージが線で追える
- ブランチ名とタグがコミットに添えて出る
- グラフ上のコミットからも差分を開ける
