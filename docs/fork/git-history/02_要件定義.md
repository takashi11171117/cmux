# cmux fork: Git 履歴・グラフ 要件定義

出所の凡例は `01_要求定義.md` §0 に同じ。

## 1. 機能要件

### FR-H01 右サイドバーに履歴モードを追加する

`RightSidebarMode` に `.history` を足す。宣言位置は `.git` の直後
`[設計判断]` — 宣言順がタブ順になる `[実コード: Sources/RightSidebarPanelView.swift:18-22]`
ため、関連するタブを隣に置く。

case 追加で埋める必要がある箇所は先行機能で洗い出し済み
`[実コード: docs/fork/git/03_詳細設計.md §2.2]`。**`switch` の網羅性で検出されない
2箇所**（`from(cliArgument:)` と `paneModes`）を忘れると、コンパイルは通り実行時に
機能しない。

- 受け入れ: 右サイドバーのタブに Git の隣で History が出る
- 受け入れ: `cmux` の CLI 引数からも選択できる
- 出所: HREQ-01

### FR-H02 コミットを新しい順に一覧表示する

各行に出すもの:

| 要素 | 内容 |
|---|---|
| 短縮ハッシュ | `%h` |
| 件名 | `%s`。1行目のみ |
| 作者 | `%an` |
| 日時 | `%aI` を相対表記に変換 |

- 受け入れ: リポジトリを開くとコミットが新しい順に並ぶ
- 受け入れ: 件名が長い場合は末尾を省略し、行の高さは変わらない
- 出所: HREQ-01

### FR-H03 履歴はページングで読む

初回は先頭 N 件だけ読み、一覧の末尾に近づいたら続きを読む。

- 受け入れ: 数万コミットのリポジトリでも、開いた瞬間に固まらない
- 受け入れ: 下までスクロールすると続きが継ぎ足され、位置は飛ばない
- 受け入れ: 履歴の最後まで到達したら、それ以上読みに行かない
- 出所: HREQ-04
- 未確定: 件数と先読み量 `[要確認: 01 §5.5]`

### FR-H04 コミットが増えたら一覧が追随する

HEAD 署名の変化を契機に先頭ページを読み直す
`[実コード: GitMetadataService+Refs.swift:62-77]`。

- 受け入れ: 別ターミナルで `git commit` すると数秒以内に一覧の先頭に現れる
- 受け入れ: ブランチを切り替えるとその履歴に入れ替わる
- 受け入れ: ファイルを保存しただけでは読み直さない（HEAD が動いていないため）
- 出所: HREQ-01

### FR-H05 行からコミットの差分を開く

行クリックで、そのコミットが変えた内容をカラムに開く。導線は先行機能の
変更ファイル一覧と同一 `[実コード: Sources/GitChangesPanelView.swift の onOpen]`。

- 受け入れ: 行をクリックすると差分がカラムに開き、赤緑の行が描画される
- 受け入れ: 何度開いても差分タブは1枚のまま
- 受け入れ: ルートコミット（親が無い）でも差分が出る
- 出所: HREQ-02

### FR-H06 リポジトリ根は先行機能と同じものを使う

`FileExplorerStore.rootPath` を使い、グループ内のセッションはグループの
ターミナルのディレクトリを借りる `[実コード: Sources/GroupDirectoryFallback.swift]`。

- 受け入れ: Git タブと History タブが常に同じリポジトリを指す
- 受け入れ: Claude セッションのように自分のディレクトリを持たない場所でも、
  グループのターミナルの履歴が出る
- 出所: HREQ-01

### FR-H07 git 管理外では静かに何も出さない

- 受け入れ: git 管理外のフォルダを開くと「履歴なし」と出てエラーにならない
- 受け入れ: 初コミット前のリポジトリでも落ちない
- 出所: HREQ-01

### FR-H08 [段階B] グラフをカラムに表示する

分岐とマージをレーンで描く。

- 受け入れ: 分岐したコミットが別レーンに、合流が線で追える
- 受け入れ: ブランチ名とタグが該当コミットに添えて出る
- 受け入れ: グラフ上のコミットからも差分を開ける
- 出所: HREQ-03
- 未確定: 描画方式 `[要確認: 01 §5.4]`

## 2. 非機能要件

### NFR-H01 git をメインスレッドで待たない

`git rev-parse` は一瞬だが `git log` は違う。同期実行するとタイピングが詰まる。
actor 越しの async にする。

先行機能では `git rev-parse --show-toplevel` を同期実行しているが
`[実コード: Sources/Panels/FilePreviewPanel.swift の gitRepositoryRoot]`、これは
stat 1回で終わるものであり、`git log` に同じ扱いは通用しない `[設計判断]`。

- 受け入れ: 大きいリポジトリで履歴を開いても、ターミナルの入力が遅れない

### NFR-H02 リポジトリをロックしない

`GIT_OPTIONAL_LOCKS=0` を渡す。先行機能と同じ `[実コード: Sources/Panels/FilePreviewPanel.swift の gitOutput]`。

- 受け入れ: 履歴を開いている状態で、別ターミナルの git 操作が待たされない

### NFR-H03 一覧の描画がタイピングを妨げない

行より下に observable を置かず、`body` から状態を書かない。upstream #2586 の
再発防止 `[実コード: CLAUDE.md「SwiftUI list boundaries」]`。

先行機能の `GitChangeTreeRow` と同じ「平坦化して1本の `ForEach`」型を使う
`[実コード: Sources/GitChangeTreeRow.swift]`。

- 受け入れ: 履歴タブを開いたままタイプしても CPU が張り付かない

### NFR-H04 スクロール中に文書を書き換えない

コードビューのバウンス `[実コード: docs/fork/技術メモ.md「シンタックス着色は文書に書くな」]`
と同じ罠を踏まない。スクロール通知の中でレイアウトを無効化する操作をしない。

- 受け入れ: 履歴を下まで回し切れる。途中で引き戻されない

### NFR-H05 ローカライズ

すべての表示文字列を `String(localized:)` にし、`Resources/Localizable.xcstrings`
に en / ja を入れる `[実コード: CLAUDE.md「Localize every user-facing string」]`。

相対日時（「2時間前」）もローカライズ対象。

### NFR-H06 既存の差分ビューアを改変しない

`cmux diff` の経路は upstream 所有。触ると追従コストになる
`[実コード: docs/fork/git/02_要件定義.md NFR-G03]`。

## 3. データ・外部インタフェース要件

### IF-H01 コミット履歴の取得

```
git log --max-count=<n> --skip=<m> \
        --pretty=format:%H%x00%h%x00%P%x00%an%x00%aI%x00%s%x00
```

`%x00`（NUL）区切り。件名に改行以外の任意文字が入りうるため、タブや `|` では
壊れる `[設計判断]`。`%P` は親のハッシュを空白区切りで返し、**マージコミットでは
複数**になる。これがグラフのレーン計算の入力になる。

### IF-H02 コミット差分の取得

```
git show --format= --patch --first-parent <sha>
```

**3種類のコミットすべてがこの1コマンドで済む**。実測 `[実測: 2026-08-27]`:

| オプション | ルート | 通常 | マージ |
|---|---|---|---|
| なし | 8行 | 7行 | **0行** |
| `--root` | 8行 | 7行 | 0行 |
| `--first-parent` | 8行 | 7行 | **7行** |

**`git show` はマージコミットの差分を既定で抑制する**。オプション無しだと出力が
空になり、呼び出し側が空パッチを捨てて**行が無反応になる**。先行機能でまったく
同じ失敗をしており `[実コード: docs/fork/技術メモ.md「git diff はステージした瞬間に空になる」]`、
そちらは `git add` 済みのファイルで、こちらはマージコミットで起きる。

`--root` は不要（`git show` はルートコミットを既定で扱える）。`--first-parent` は
通常コミットに付けても出力が変わらないので、**分岐せず常に付ける**。

`-c` / `--cc` は 0 行のままなので使えない。`-m` は親ごとに差分を出すため、
マージでは同じ変更が親の数だけ並ぶ。

「コマンドは成功するが出力が空」という失敗は画面にもログにも出ないので、
**判断は値型に切り出してテストする**（先行機能の `GitFilePatchCommand` と同じ形）。

### IF-H03 ブランチ・タグの取得（段階B）

```
git log --pretty=format:%H%x00%D
```

`%D` が ref 名を返す。

### IF-H04 カラムへ開く

差分は既存の `openFileDiffInCodeReviewColumn` 系の経路
`[実コード: Sources/AppDelegate.swift:7063]`。グラフは
`CodeReviewPanelState.showBrowser(url:)` `[実コード: Sources/CodeReviewPanelState.swift:112]`。
