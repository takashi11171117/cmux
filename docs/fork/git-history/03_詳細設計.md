# cmux fork: Git 履歴・グラフ 詳細設計

出所の凡例は `01_要求定義.md` §0 に同じ。

## 1. 全体像

```
FileExplorerStore.rootPath ──┐
GroupDirectoryFallback ──────┴─→ リポジトリ根
                                    │
                          GitHistoryService (actor)
                            │  git log をページ単位で実行
                            │  git show でコミット差分
                            ↓
                     GitHistoryStore (@MainActor @Observable)
                            │  ページの連結・重複排除・末尾判定
                            ↓
              GitHistoryPanelView（右サイドバー .history タブ）
                            │  行クリック
                            ↓
              AppDelegate.openCommitDiffInCodeReviewColumn
                            ↓
                     コードレビューカラム（既存）
```

段階Bのグラフは `GitHistoryStore` の同じデータを入力に、レーンを計算して
カラムに描く。**一覧とデータ源を共有する**ので、Bのために A を作り直さない。

## 3. データ層

### 3.1 `GitHistoryCommand`（値型・テスト対象）

「どの git コマンドを打つか」だけを決める。先行機能の `GitFilePatchCommand` と
同じ形 `[実コード: Sources/GitFilePatchCommand.swift]`。

```swift
struct GitHistoryCommand: Equatable, Sendable {
    let arguments: [String]
    init(maxCount: Int, skip: Int)
}

struct GitCommitPatchCommand: Equatable, Sendable {
    let arguments: [String]
    init(sha: String)
}
```

`GitCommitPatchCommand` は**常に `--first-parent` を付ける**。マージコミットの
差分が既定で抑制され、出力が空になって行が無反応になるため `[実測: 02 §IF-H02]`。
通常コミットに付けても出力は変わらない。

このクラスの失敗は「コマンドは成功するが出力が空」で、画面にもログにも出ない。
**リポジトリ無しでテストできる形にしておかないと再発に気づけない**
`[実コード: docs/fork/技術メモ.md「git diff はステージした瞬間に空になる」]`。

### 3.2 `GitCommitLine`（値型・テスト対象）

`git log` の1レコードをパースする。

```swift
struct GitCommitLine: Equatable, Sendable {
    let sha: String
    let shortSHA: String
    let parents: [String]
    let authorName: String
    let authoredAt: Date
    let subject: String

    static func parse(_ record: String) -> GitCommitLine?
    static func parseAll(_ output: String) -> [GitCommitLine]
}
```

区切りは NUL（`%x00`）。件名に改行以外の任意文字が入りうるので、タブや `|` では
壊れる `[設計判断]`。

`parents` が空ならルートコミット、2つ以上ならマージコミット。グラフのレーン計算の
入力になる。

### 3.3 `GitHistoryService`（actor）

```swift
actor GitHistoryService {
    func page(repositoryRoot: String, maxCount: Int, skip: Int) async -> [GitCommitLine]
    func patch(repositoryRoot: String, sha: String) async -> String?
}
```

**actor にする理由**: `git rev-parse` は stat 1回で終わるので同期実行が許されるが
`[実コード: Sources/Panels/FilePreviewPanel.swift の gitRepositoryRoot]`、
`git log` は所要時間がリポジトリ規模に比例する。メインスレッドで待つと
タイピングが詰まる `[実コード: CLAUDE.md「Typing-latency-sensitive paths」]`。

`GIT_OPTIONAL_LOCKS=0` を渡す `[実コード: 同 gitOutput]`。

### 3.4 `GitHistoryStore`（@MainActor @Observable）

```swift
@MainActor
final class GitHistoryStore {
    private(set) var commits: [GitCommitLine] = []
    private(set) var isLoading = false
    private(set) var reachedEnd = false

    func setRepositoryRoot(_ path: String?)
    func loadNextPageIfNeeded(visibleIndex: Int)
    func refreshIfHeadChanged()
}
```

**重複排除は SHA で行う**。ページ境界でコミットが増えると `--skip` がずれ、
同じコミットが2度来る `[設計判断]`。

**末尾判定は「返ってきた件数 < 要求件数」**。空が返るまで問い続けると、履歴の
最後で無駄な `git log` を回し続ける。

### 3.5 更新契機

`gitHeadSignature(repository:)` の変化を見る
`[実コード: Packages/macOS/CmuxGit/Sources/CmuxGit/Parsing/GitMetadataService+Refs.swift:62-77]`。

ファイル保存のたびに `git log` を回さない。HEAD が動いたときだけ先頭ページを
読み直す。ブランチ切り替えも HEAD の変化として検出される。

## 4. 一覧 UI

### 4.1 SwiftUI 構造の制約

先行機能とまったく同じ制約が効く。

- **行より下に observable を置かない**。行は値とクロージャだけを受け取る
- **`body` から状態を書かない**

どちらも upstream #2586 の 100% CPU スピンループの再発条件
`[実コード: CLAUDE.md「SwiftUI list boundaries」]`。

`GitChangeTreeRow` と同じく、**平坦化した行を1本の `ForEach` に流す**
`[実コード: Sources/GitChangeTreeRow.swift]`。

### 4.2 ページの継ぎ足し

`onAppear` を行に付けて可視インデックスを拾い、末尾に近づいたら次を読む。

**`body` から `loadNextPageIfNeeded` を呼ばない**。`onAppear` は body 評価では
なくビューの出現で走るので、この制約に触れない `[設計判断]`。

### 4.3 表示要素

```
a1b2c3d  fix(fork): コードビューのバウンスを直す      2時間前  takashi
16beda0  test(fork): red を示す                     2時間前  takashi
```

件名は `lineLimit(1)` + 末尾省略。行の高さは固定にする（可変にすると
スクロール量の計算が狂う）`[設計判断]`。

相対日時はローカライズ対象 `[実コード: CLAUDE.md「Localize every user-facing string」]`。

## 5. コミット差分を開く

### 5.1 経路

先行機能の `openFileDiffInCodeReviewColumn` と同じ構造で、パッチの作り方だけが
違う `[実コード: Sources/AppDelegate.swift:7063]`。

```
GitCommitPatchCommand(sha:) → git show → パッチ文字列
    → cmux diff - --code-review-column（既存の CLI 経路）
    → カラムにブラウザサーフェス
```

**既存の差分ビューアを改変しない**。パッチを標準入力に流すだけ
`[実コード: docs/fork/git/02_要件定義.md NFR-G03]`。

### 5.2 環境変数の除去を忘れない

`CMUX_WORKSPACE_ID` / `CMUX_SURFACE_ID` / `CMUX_SOCKET` を消す。残すと CLI が
分割元のペインを探しに行き、**カラムではなくターミナルが分割される**
`[実コード: Sources/AppDelegate.swift の openFileDiffInCodeReviewColumn 内のコメント]`。

先行機能でこれを踏んでいる。CLI 単体のテストでは再現せず、GUI から呼んだときだけ
壊れる。

## 6. 段階B：グラフ

### 6.1 レーン計算（値型・テスト対象）

```swift
struct GitGraphLane: Equatable, Sendable {
    let commitIndex: Int
    let lane: Int
    let parentLanes: [Int]
}

enum GitGraphLayout {
    static func lanes(for commits: [GitCommitLine]) -> [GitGraphLane]
}
```

新しい順に走査し、各コミットに空きレーンを割り当てる。親が既にレーンを持っていれば
それを引き継ぎ、マージ（親が2つ以上）では2本目以降を別レーンから合流させる。

**ここが段階Bの本体**。値型なので、リポジトリ無しで分岐・マージ・ルートの各形を
テストできる。

### 6.2 描画方式

`[要確認: 01 §5.4]` — `file://` か独自スキームか。着手直前に決める。

判断材料:
- `showBrowser(url:)` は差分を**スキーム**で、それ以外を**完全一致**で照合する
  `[実コード: Sources/CodeReviewPanelState.swift:127-134]`。固定パスの `file://` なら
  完全一致でタブが1枚に保たれる
- 差分ビューアは `bypassRemoteProxy: true` を必要とした `[実コード: 同 136-150]`。
  同じ配慮が要る可能性がある
- 独自スキームの登録は upstream 所有の経路にある `[実コード: Sources/TerminalController.swift:6933]`

## 8. テスト方針

値型に切り出したものはリポジトリ無しでテストする。

| 対象 | 内容 |
|---|---|
| `GitCommitPatchCommand` | **マージコミットで `--first-parent` が付く**こと。これが抜けると行が無反応になる |
| `GitHistoryCommand` | `--max-count` / `--skip` の組み立て |
| `GitCommitLine.parse` | NUL 区切り、件名に区切り文字が入る場合、親0個/1個/複数 |
| `GitHistoryStore` | ページ連結、SHA での重複排除、末尾判定 |
| `GitGraphLayout` | 直線・分岐・マージ・ルートの各形（段階B） |

GUI の回帰は手動テスト仕様書に項目を足す。
