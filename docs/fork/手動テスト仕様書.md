# Agent-first IDE 手動統合テスト仕様書

自動テストで届かない部分だけを列挙する。ユニットテストは 130 件通っており、値型・ポリシー・
コーディネータ・エンジン・行インデックスの正しさはそこで担保されている。ここに書くのは
**実際に描画してみないと分からないこと**と、**複数の入口をまたぐ振る舞い**に絞る。

## 事前準備

```bash
./scripts/reload.sh --tag agent-first-ide --launch
```

テスト用ファイルを用意しておく。

```bash
mkdir -p /tmp/afide-manual && cd /tmp/afide-manual
printf 'import Foundation\n// line comment\nlet greeting = "hello"\nlet count = 42\n/* block\n   comment */\n' > sample.swift
printf 'const x: number = 1; // note\n' > sample.ts
printf 'void main() { var x = 1; }\n' > sample.dart
printf 'no known grammar here\n' > sample.foo
python3 -c "print('x = 1\n' * 200000)" > huge.py          # 約 1.2 MB
python3 -c "print('y = 2\n' * 30000)" > big.py            # 約 180 KB
```

> **⚠️ テスト中はユーザーの本番 cmux を終了しておくこと。** タグ付きビルドは別バンドル ID を持つが、
> テストで起動する untagged な `cmux DEV.app` が既定のデバッグソケットとセッションファイルを共有する。

## 🔴 必須（ここが壊れていたらマージしない）

### A. ハイライトの基本描画

- [ ] **A-1 色が出る**: `/tmp/afide-manual/sample.swift` を File Explorer からダブルクリック → `import` / `let` がキーワード色、`"hello"` が文字列色、`// line comment` がコメント色、`42` が数値色で、いずれも本文色と**異なる**
- [ ] **A-2 ブロックコメントが最後まで色付く**: 同ファイルの `/* block` から `comment */` まで**2行にまたがって**コメント色になっている（1行目だけ色が付いて2行目が素になっていたら失敗）
- [ ] **A-3 未対応拡張子はプレーン**: `sample.foo` を開く → 色は付かないが、**本文は欠落せず全部表示され、編集もできる**
- [ ] **A-4 Dart は現状プレーン**: `sample.dart` を開く → **色が付かないのが期待どおり**（同梱 highlight.js に dart 文法が無い。FR-02 未達として既知）

### B. テーマ連動（最も壊しやすい箇所）

- [ ] **B-1 ライト/ダーク両方で読める**: `sample.swift` を開いたまま、システム外観をライト→ダーク→ライトと切り替える → **再起動なしで**配色が変わり、どちらでも全トークンが背景に対して判読できる
- [ ] **B-2 色が塗り潰されない**: `sample.swift` を開いたまま、**別パネルをクリックする / タブを切り替えて戻る / ウィンドウをリサイズする**を数回繰り返す → ハイライトが本文色一色に戻らない
  - これは `applyTheme` が SwiftUI 更新のたびに `textView.textColor` を全体へ代入する挙動を回避できているかの確認。**回帰しやすい最重要項目**
- [ ] **B-3 スクロール先も色が付いている**: 大きめのファイル（`big.py`）を開き、**一気に最下部までスクロール** → 到達した領域が黒一色（ダークテーマなら読めない状態）になっていない

### C. 保存衝突（唯一の既存挙動変更）

- [ ] **C-1 バナーが出る**: `sample.swift` を開いて**保存せずに1文字打つ** → 別ターミナルで `echo "changed" >> /tmp/afide-manual/sample.swift` → **「This file changed on disk」バナーが出る**
- [ ] **C-2 Keep Mine**: バナーで Keep Mine → バナーが消え、**エディタの内容は自分の編集のまま**、未保存マークも残る → Cmd+S で保存するとディスク側が自分の内容で上書きされる
- [ ] **C-3 Reload**: 同じ状況を作り直して Reload → **エディタの内容がディスク側に置き換わり**、未保存マークが消える
- [ ] **C-4 クリーンなら出ない**: 何も編集していない状態で外部から書き換える → **バナーは出ず**、内容が自動で更新される（従来どおり）
- [ ] **C-5 自分の保存では出ない**: 編集して Cmd+S → **バナーが出ない**（自分の保存がファイル監視経由で返ってくるだけなので）
- [ ] **C-6 ファイルが消えたらバナーも消える**: バナーが出ている状態で `rm /tmp/afide-manual/sample.swift` → バナーが消え、ファイル無しの表示になる

### D. 行番号

- [ ] **D-1 番号と本文が揃う**: `sample.swift` を開く → 左端に 1 から始まる行番号が出て、各行と縦位置が一致
- [ ] **D-2 折り返しでも1行1番号**: 設定で `fileEditor.wordWrap` をオンにし、横幅を超える長い行を含むファイルを開く → **折り返された2行目以降には番号が出ない**
- [ ] **D-3 ズームで崩れない**: ⌘+ / ⌘- を数回、およびトラックパッドのピンチ → 行番号の**文字サイズも一緒に変わり**、本文との縦位置が一致し続ける
- [ ] **D-4 桁が増えても切れない**: `huge.py`（20万行）を開いて最下部へ → 6桁の行番号が表示され、**本文が水平に切れていない**

## 🟡 推奨

### E. 設定のライブ反映

- [ ] **E-1 ハイライト切替**: エディタを開いたまま Settings → App → Syntax Highlighting をオフ → **再起動なしで**色が消え、本文がテーマの前景色になる → オンに戻すと色が戻る
- [ ] **E-2 行番号切替**: 同様に Line Numbers をオフ → ルーラが消える → オンで戻る
- [ ] **E-3 cmux.json から**: `~/.config/cmux/cmux.json` に `"fileEditor": { "syntaxHighlight": false, "lineNumbers": false }` を書いて保存 → 設定画面のトグルが両方オフになる
- [ ] **E-4 コマンドパレット**: ⌘K で "Syntax Highlighting" / "Line Numbers" を検索 → 出てきて、選ぶとトグルできる
- [ ] **E-5 設定検索**: Settings の検索欄に `syntax` / `line numbers` / `fileEditor.syntaxHighlight` → 該当行にジャンプする

### F. 入口別のルーティング

同じファイルを3つの入口から開き、**どれも同じように色と行番号が出る**ことを確認する。

- [ ] **F-1 File Explorer**: ダブルクリック
- [ ] **F-2 ターミナル Cmd-click**: `echo /tmp/afide-manual/sample.swift` して出力を Cmd-click
- [ ] **F-3 CLI**: `CMUX_TAG=agent-first-ide scripts/cmux-debug-cli.sh` 経由で `cmux open /tmp/afide-manual/sample.swift`
  - **`/tmp/cmux-cli` は使わないこと**（ユーザーの本番アプリのソケットを叩く恐れ）
- [ ] **F-4 新規拡張子**: `.dart` / `.php` / `.mjs` / `.cjs` / `.cxx` / `.hh` の各ファイルを開く → **QuickLook を経由せず**最初からテキストとして開く（一瞬プレビュー表示が挟まったら失敗）

### G. 外部エディタへの行番号（AFIDE-14）

前提: Settings で `app.preferredEditor` に行番号付きコマンドを設定する。VS Code なら `code --goto {file}:{line}`。

- [ ] **G-1 指定行で開く**: `sample.swift` の3行目にカーソルを置く → ヘッダの共有メニュー → **「Open in Editor at Line 3」** → VS Code が3行目にカーソルを置いて開く
- [ ] **G-2 プレースホルダ無しでも壊れない**: `app.preferredEditor` を `code` だけにする → メニュー項目は出るが、ファイルが（行指定なしで）普通に開く
- [ ] **G-3 テキスト以外では出ない**: PNG や PDF を開く → **「Open in Editor at Line N」項目が出ない**
- [ ] **G-4 行番号オフでも動く**: Line Numbers 設定をオフにする → G-1 が**同じ行番号で**動く（カーソル行は行番号ルーラとは独立に計算されるため）
- [ ] **G-5 既存の「Open in <App>」が無事**: 同じメニューの従来項目からも、これまでどおり開く

### H. Markdown パネル

- [ ] **H-1 テキスト編集モードでも色が付く**: `.md` を Markdown ビューアで開き、テキスト編集モードに切り替える → ハイライトと行番号が出る
- [ ] **H-2 Markdown の保存衝突**: Markdown のテキスト編集モードで未保存編集を作り、外部から書き換える → バナーが出て Reload / Keep Mine が効く

## 🟢 任意（性能・大規模）

- [ ] **I-1 大きいファイルでも即座に開く**: `huge.py`（1.2 MB / 20万行）を開く → **開くこと自体は待たされない**（色は後から付いてよい）
- [ ] **I-2 サイズ上限でプレーンに落ちる**: 1.5 MB を超えるソースファイルを作って開く → 色は付かないが本文は全部出て編集できる
- [ ] **I-3 タイピングが引っかからない**: `big.py`（18万文字）で連続入力 → **文字が取りこぼされない**、カーソルが飛ばない

## テスト優先度

| 優先度 | 項目 | 理由 |
|---|---|---|
| 🔴 必須 | B-2（色が塗り潰されない） | `applyTheme` は SwiftUI 更新のたびに走る。ここの回避が崩れると、一見動いているのに操作した瞬間に色が消える。ユニットテストでは1パスしか再現できない |
| 🔴 必須 | C-1〜C-6（保存衝突） | **唯一の既存挙動変更**。誤検知すると保存のたびにバナーが出て邪魔になり、検知漏れすると編集内容を失う |
| 🔴 必須 | R-8（Session Restore） | NFR-01 が最優先の制約。壊すと全ユーザーの作業状態が失われる |
| 🔴 必須 | B-3（スクロール先の色） | 未描画領域が `NSTextView` 既定の黒になると、ダークテーマで**読めなくなる** |
| 🟡 推奨 | D-3（ズーム同期） | 実装中にキャッシュ由来のバグを1件踏んでいる箇所 |
| 🟡 推奨 | F-1〜F-4（入口別） | Shared behavior policy の要求。1入口だけ直して他が漏れる典型 |
| 🟡 推奨 | G-1〜G-5（外部エディタ） | 新規-G の判断が妥当だったかの実機確認 |
| 🟢 任意 | I-1〜I-4（性能） | 数値目標が未確定（未確定-08）。体感で判断するしかない |
