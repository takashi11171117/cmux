# cmux fork: Git ステージ操作 要件定義

出所の凡例は `01_要求定義.md` §0 に同じ。

## 1. 機能要件

### FR-S01 データモデルの staged/unstaged 分離

`GitEntryStatus` を新設し、`GitStatusProvider.parseGitStatus` はキーごとに
`GitEntryStatus` を返す。

- 受け入れ: XY = `M ` は `staged=modified, unstaged=nil`
- 受け入れ: XY = ` M` は `staged=nil, unstaged=modified`
- 受け入れ: XY = `MM` は `staged=modified, unstaged=modified`
- 受け入れ: XY = `??` は `staged=nil, unstaged=untracked`
- 受け入れ: XY = `A ` は `staged=added, unstaged=nil`
- 受け入れ: XY = `AM` は `staged=added, unstaged=modified`
- 受け入れ: XY = `R ` は `staged=renamed, unstaged=nil` （2 パス消費）
- 受け入れ: XY = ` D` は `staged=nil, unstaged=deleted`
- 出所: SREQ-04

### FR-S02 既存 `gitStatusByPath` は互換維持

既存の `FileExplorerStore.gitStatusByPath: [String: GitFileStatus]` は
`GitEntryStatus` から派生（`unstaged ?? staged` のような優先ルールで潰す）して
そのまま提供する。既存の File Explorer セル色分けが壊れない。

- 受け入れ: File Explorer の変更マーク色が現行と同じ
- 出所: SREQ-04（後方互換）

### FR-S03 2 セクション表示

Git タブは上から「Staged Changes」「Changes」の 2 セクション。両方とも
`GitChangeTreeRow` と同じフォルダ畳めるツリー表示。両セクションで**同じ折りたたみ状態**
を共有せず、独立に持つ `[設計判断]`。

- 受け入れ: セクションヘッダにファイル数を表示
- 受け入れ: 該当ファイルが無いセクションは非表示（見出しごと消える）
- 出所: SREQ-04

### FR-S04 行の Stage / Unstage / Discard ボタン

- Changes セクションの行: `+`（stage）と `↺`（discard）
- Staged Changes セクションの行: `−`（unstage）のみ
- ボタンは行 hover で表示 `[要確認: 5.1]`

- 受け入れ: `+` 押下で `git add -- <path>`
- 受け入れ: `−` 押下で `git reset -- <path>`（HEAD が無い時は `git rm --cached <path>`）
- 受け入れ: `↺` 押下で確認ダイアログ → OK なら
  未追跡は削除、追跡済みは `git checkout -- <path>`
- 受け入れ: 操作後、数秒以内に一覧が更新される
- 出所: SREQ-01, SREQ-02, SREQ-03

### FR-S05 差分の staged/unstaged 振り分け

- Staged セクションの行クリック → `git diff --cached -- <path>` をカラムに開く
- Changes セクションの行クリック → `git diff -- <path>`（**ワークツリーとインデックスの差**）
  をカラムに開く

新規追加ファイル（未追跡）は `git diff --no-index /dev/null <path>` を使う。既存の
`GitFilePatchCommand` にステージ側の分岐を追加する形にする。

- 受け入れ: MM ファイルは Staged 側で staged 差分、Changes 側で unstaged 差分が出る
- 受け入れ: マージコミット処理は不要（作業ツリー差分なので `--first-parent` 不要）
- 出所: SREQ-05

### FR-S06 [要確認] ボタン UI の位置

hover で右端に絶対配置するか、常時表示するか、実装中に判断。

## 2. 非機能要件

### NFR-S01 git をメインスレッドで待たない

`git add / reset / checkout` は一瞬だが、`git status` は大きいリポジトリで遅い。
既に `GitStatusProvider` は `DispatchQueue.global(qos: .utility)` で回している
`[実コード: Sources/FileExplorerStore.swift:849-865]`。ステージ操作も同じ扱い。

`GIT_OPTIONAL_LOCKS=0` を渡す。既存経路と同じ `[実コード: 同]`。

### NFR-S02 リストが再描画で失敗しない

`GitChangesPanelView` は既に「行より下に observable を置かない」で作られている
`[実コード: docs/fork/技術メモ.md「SwiftUI list boundaries」]`。2 セクション化しても
その規約を維持する。

### NFR-S03 破壊的操作は必ず確認

Discard は失敗すると復旧できない。既存の Move to Trash と同様、確認ダイアログを出す
`[実コード: Sources/FileExplorerContextMenuActions.swift の contextMenuMoveToTrash]`。

### NFR-S04 ローカライズ

「Staged Changes」「Changes」「Discard Changes」「Are you sure?」を en / ja で用意する
`[実コード: CLAUDE.md「Localize every user-facing string」]`。

## 3. データ・外部インタフェース要件

### IF-S01 git status 出力の XY 解析

```
git status --porcelain=v1 -z
```
既存のコマンド `[実コード: Sources/GitStatusProvider.swift:28]`。パーサだけ変更。

### IF-S02 ステージ操作

```
git add -- <path>
git reset -- <path>       # HEAD あり
git rm --cached -- <path> # HEAD 無し (初コミット前)
git checkout -- <path>    # 追跡済みを discard
rm -f <path>              # 未追跡を discard (Finder Trash に入れる方が良いかは要確認)
```

- 受け入れ: 未追跡の discard も**ゴミ箱**に入れる `[設計判断]`。存在パスから削除
  してしまうと復旧不能。既存の Move to Trash と同じ `FileManager.trashItem(at:)` を使う

### IF-S03 差分の staged/unstaged

`GitFilePatchCommand` を拡張:
```
git diff -- <path>              # unstaged
git diff --cached -- <path>     # staged
git diff --no-index /dev/null <path>  # untracked (今と同じ)
```
