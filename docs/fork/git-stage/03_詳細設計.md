# cmux fork: Git ステージ操作 詳細設計

出所の凡例は `01_要求定義.md` §0 に同じ。

## 1. 全体像

```
git status --porcelain=v1 -z
     │
     ▼
GitStatusProvider.parseGitStatus   → [String: GitEntryStatus]
     │
     ▼
FileExplorerStore
  ├─ gitEntryStatusByPath   (新)   [String: GitEntryStatus]
  └─ gitStatusByPath        (旧)   [String: GitFileStatus]  ← 派生・互換
     │
     ▼
GitChangesPanelView
  ├─ Staged Changes セクション (staged != nil)
  └─ Changes セクション        (unstaged != nil)
     │  各行の hover
     ▼
  GitStageOperation actor
     ├─ stage(path)      → git add
     ├─ unstage(path)    → git reset / rm --cached
     └─ discard(path)    → git checkout / Trash

     行クリック
     ▼
  GitFilePatchCommand (拡張)
     ├─ init(filePath: side: .staged)    → git diff --cached
     ├─ init(filePath: side: .unstaged)  → git diff
     └─ init(filePath: side: .untracked) → git diff --no-index /dev/null
```

## 2. データ層

### 2.1 `GitEntryStatus`（値型・テスト対象）

```swift
struct GitEntryStatus: Equatable, Sendable {
    let staged: GitFileStatus?
    let unstaged: GitFileStatus?

    var hasAny: Bool { staged != nil || unstaged != nil }
    /// 既存 API 互換用: どちらか片方を代表として返す（unstaged 優先）。
    var displayStatus: GitFileStatus? { unstaged ?? staged }
}
```

### 2.2 `GitStatusProvider.parseGitStatus` の書き換え

現行の `parseStatusChars(index:workTree:)` は 1 値を返す。これを

```swift
private func parseXY(index: Character, workTree: Character) -> GitEntryStatus? {
    let staged   = mapChar(index)         // 空白 or `?` は nil
    let unstaged = mapChar(workTree)      // 同上
    guard staged != nil || unstaged != nil else { return nil }
    return GitEntryStatus(staged: staged, unstaged: unstaged)
}

private func mapChar(_ c: Character) -> GitFileStatus? {
    switch c {
    case "M", "T", "U": return .modified
    case "A", "C":       return .added
    case "D":            return .deleted
    case "R":            return .renamed
    case "?":            return .untracked
    default:             return nil       // ' ' もここに落ちる
    }
}
```

に置き換える。**`??` の扱いに注意**: `parseXY('?', '?')` は `staged=untracked, unstaged=untracked` に
なるが、これは間違い。git 慣習では untracked は unstaged 扱いなので、`??` は
明示的に「staged=nil, unstaged=untracked」に補正する。

### 2.3 既存 API 互換

`FileExplorerStore.gitStatusByPath` は残す。実装は

```swift
gitStatusByPath = gitEntryStatusByPath.compactMapValues(\.displayStatus)
```

で導出。File Explorer のセル色分けは変わらない。

### 2.4 テスト

`GitStatusProviderTests` に XY 全パターンを追加。既存テストは
`gitStatusByPath` を使い続けるので影響なし。

## 4. 操作層

### 4.1 `GitStageOperation` actor

```swift
actor GitStageOperation {
    func stage(repositoryRoot: String, path: String) async
    func unstage(repositoryRoot: String, path: String) async
    func discardUnstagedChanges(repositoryRoot: String, path: String, isUntracked: Bool) async throws
}
```

- `stage` → `git add -- <path>`
- `unstage` → `git reset -- <path>` (HEAD あり) or `git rm --cached -- <path>` (無し)
- `discard` → 未追跡なら `FileManager.trashItem(at:)`、追跡済みなら `git checkout -- <path>`

いずれも `GIT_OPTIONAL_LOCKS=0` 環境で `Process` 実行。既存 `GitFilePatchCommand` の
`gitOutput` パターンを踏襲。

### 4.2 操作後の再取得

操作の完了を待って `FileExplorerStore.refreshGitStatus()` を呼ぶ。既に directory
watcher で自動的に refresh される仕組みはあるが、明示的に呼んで UI 反映を早くする。

### 4.3 discard の確認ダイアログ

```swift
let alert = NSAlert()
alert.messageText = "Discard changes to <name>?"
alert.informativeText = "This cannot be undone."
alert.addButton(withTitle: "Discard")
alert.addButton(withTitle: "Cancel")
alert.alertStyle = .warning
let button = alert.runModal()
guard button == .alertFirstButtonReturn else { return }
```

未追跡ファイルの discard は Trash に入れる（`FileManager.trashItem(at:)`）。
既存の Move to Trash 実装を再利用 `[実コード: Sources/FileExplorerContextMenuActions.swift]`。

## 5. 差分層

### 5.1 `GitFilePatchCommand` の拡張

```swift
enum Side { case staged, unstaged, untracked }

struct GitFilePatchCommand {
    init(filePath: String, side: Side) {
        switch side {
        case .untracked:
            arguments = ["diff", "--no-index", "--", "/dev/null", filePath]
        case .staged:
            arguments = ["diff", "--cached", "--", filePath]
        case .unstaged:
            arguments = ["diff", "--", filePath]
        }
    }
}
```

`hasHead` は不要 `[実測: 2026-09-03 unborn ブランチで git diff --cached / git diff を実行]`。
`--cached` は HEAD が無ければ空ツリーと比較し、`git diff` は HEAD を見ない。
初コミット前の `AM` ファイルでも staged (`+a`) と unstaged (`+b`) が別内容で出る。
当初案の「HEAD 無しは `--no-index /dev/null` に倒す」は両行が同じ全文パッチになる誤りだった
（Codex レビュー指摘 1.1）。

既存の `init(filePath:isUntracked:hasHead:)` は削除せず deprecated 扱い or wrapper で
`side` を推論するようにする（すべての呼び出し元を書き換える方が clean）。

### 5.2 呼び出し側

`GitChangesPanelView` の行 `onOpen`:

```swift
let side: GitFilePatchCommand.Side =
    section == .staged ? .staged
    : (entry.unstaged == .untracked ? .untracked : .unstaged)
AppDelegate.shared?.openFileDiffInCodeReviewColumn(
    filePath: entry.path,
    side: side,
    repositoryRoot: root
)
```

`AppDelegate.openFileDiffInCodeReviewColumn` の引数を `isUntracked: Bool` から
`side: Side` に変える。既存の呼び出し元は 1 箇所 `[実測]`。
